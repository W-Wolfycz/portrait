# 群像（Portrait）

群像会从 `chat_memory` 的聊天记录里，按群聊或私聊整理人物画像与群画像，并提供一个按需查询的工具。它不会改写聊天记录，也不会把画像自动塞进对话。

## 功能

- **按会话隔离**：每个群、每个私聊单独整理；同一个群的多 BOT 共用一份画像，不跨会话混用。
- **两类画像**：每个群一份群画像；每个发言者一份人物画像。
- **内容随聊天更新**：记录长期特征、近期状态、群氛围、规则和成员关系。
- **每日整理**：自动把当天的聊天整理进画像；也可以手动触发。
- **按需查询**：模型可调用 `portrait_query` 查询群画像或人物画像。
- **黑名单**：指定群或私聊不参与整理和查询。

## 安装

需要：

- AstrBot 4.29 或更高版本；
- `chat_memory` 1.6.0-beta 或兼容的 V2 数据结构。

把本目录放到：

```text
data/plugins/portrait/
```

在 WebUI 启用插件，并为画像任务选择一个模型即可。CM 数据库、画像数据库和时区都不需要手动配置。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `llm_provider` | "" | 画像整理和查询使用的模型；留空跟随默认对话模型 |
| `extract_threshold` | 50 | 每累计多少条文字消息做一次整理 |
| `initial_cursor` | latest | 新会话首次处理范围：latest 只处理启用后的新消息；oldest 回填历史 |
| `extract_retry_attempts` | 1 | 同一片段萃取失败后立即重试次数；0 = 只等下一轮扫描 |
| `flush_min_units` | 10 | 低活跃会话每日整理所需的最小消息数 |
| `flush_time` | 04:00 | 低活跃会话的每日整理时间（HH:MM） |
| `merge_time` | 04:00 | 每日把整理结果合并进画像的时间（HH:MM） |
| `tick_seconds` | 60 | 扫描间隔（秒）；智能扫描开启时作为上限 |
| `smart_scan` | true | 有积压时缩短间隔，空闲时放大，最多回到扫描间隔 |
| `max_segments_per_scan` | 20 | 每轮最多处理多少段对话 |
| `max_segments_per_merge` | 0 | 群画像分批容量；0 表示一次完成，不拆分 |
| `llm_max_concurrency` | 4 | 同时进行的模型调用上限；1 表示串行 |
| `failure_advance_after` | 3 | 连续失败多少次后跳过卡住的内容；0 表示不因普通失败跳过 |
| `extract_refusal_advance_messages` | 5 | 内容被安全策略拒绝或连续失败时，跳过多少条消息 |
| `merge_refusal_advance_segments` | 5 | 合并被安全策略拒绝或连续失败时，跳过多少段内容 |
| `segment_ttl_days` | 7 | 尚未合并进画像的内容保留天数；0 表示不清理 |
| `enable_group_profile` | true | 是否生成群画像 |
| `enable_person_profile` | true | 是否生成人物画像 |
| `blacklist_sessions` | [] | 黑名单，格式 `G:群号` 或 `F:私聊号` |
| `llm_timeout_seconds` | 120 | 单次模型调用超时（秒） |

插件启用后自动运行，禁用或重载后停止；没有额外的总开关。

## 使用

### 查看画像

在 WebUI 的插件详情页打开「群像」页面，默认停在**概览**：

- 运行状态、最近扫描与最近合并时间；
- 待合并片段、画像数量、字段年龄、7 天合并失败、不稳定字段；
- 近两周合并趋势折线（合并次数 + token 消耗）；
- 失败明细：按错误类型聚合，能看出是 LLM 超时、JSON 解析失败还是内容政策拒绝。

切到「画像」标签查看具体内容：

- 左侧列出所有已生成画像的群聊和私聊，显示群名/好友名和头像；
- 右侧分「群画像 / 人物」查看；
- 人物列表支持搜索，点开可看完整画像；
- 同名人物在列表里用头像和 QQ 号区分；
- 支持手动编辑：群画像和人物画像都可以新增、修改、删除字段；编辑页给出英文 key + 中文说明，常用字段可点选；
- 每次覆盖前自动留版本快照，可查看字段时效、合并 diff（新增/修改/删除/跨层搬动）并一键回滚；
- 支持删除人物画像或整份群画像（删除会先确认）；
- 默认把当前会话的群画像和当前说话者画像注入每轮 LLM 临时上下文，可在配置关闭 `inject_context`；
- 手动修改会成为下一次自动合并的起点，后续仍可能被 LLM 调整。

这个页面只读取画像，不会把内容发送到聊天或注入对话。

### 命令

- `/portrait status`：查看运行状态、画像数量和待处理内容。
- `/portrait segments [N]`：查看当前会话最近片段摘要（含已消费）。
- `/portrait me`：获取自己的画像图片；别名 `/画像`。
- `/portrait group`：获取当前群画像图片；别名 `/群画像`。
- `/portrait person [昵称/QQ]`：获取指定人物画像图片，留空为自己。
- `/portrait delete [昵称/QQ|group]`：管理员删除人物画像或整份群画像；别名 `/删除画像`。
- `/portrait restore [版本号]`：管理员列出/回滚群画像历史版本。
- `/portrait merge`：管理员立即合并一次画像。
- `/portrait scan`：管理员立即扫描一轮新消息。

### 查询工具

```text
portrait_query(is_group, target, question)
```

- `is_group=true`：查询当前群的群画像；私聊没有群画像。
- `is_group=false`：查询人物画像；`target` 留空表示当前发送者。
- 只查询当前会话，不会跨群或跨私聊；黑名单会话返回“未启用”。

`target` 可以填 QQ 号或名称。名称会先查群成员目录，再查已有画像；遇到同名多人时会要求用 QQ 号指定，不会随便猜一个。

## 数据与隐私

- 只读取 `chat_memory` 的聊天记录；画像保存在群像自己的数据库中。
- 不保存聊天原文、引用或证据；只保存整理后的画像和临时整理结果。
- 画像按会话隔离，不跨群合并。
- 画像不会自动删除；黑名单只停止后续整理和查询，旧画像保留。
- 未合并的临时内容超过 `segment_ttl_days` 会被清理。

## 常见问题

**为什么查询显示“暂无记录”？**  
画像需要先扫描并合并。等到每日合并时间，或管理员执行 `/portrait merge`。

**首次启用会从哪里开始？**  
默认从启用后的新消息开始，不会全量回填历史。把 `initial_cursor` 改为 `oldest`，新建的会话游标才会从最早的历史消息开始回填。已有游标不受这个配置影响。

**部署后才改成 oldest，会补历史吗？**  
不会。已经前进的游标不会倒退，`oldest` 只影响之后新建的会话。要全量重建，需要清空画像库后重新扫描和合并。

**为什么私聊没有群画像？**  
群画像只对群聊生成；私聊只有人物画像。

**画像会进入聊天提示词吗？**  
不会自动进入。模型只在需要时调用 `portrait_query` 查询，查询结果由模型决定怎么使用。

**模型调用太多怎么办？**  
调低 `llm_max_concurrency`，设为 1 即完全串行。
